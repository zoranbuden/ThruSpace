# Contributing

Feedback is genuinely wanted, and it is the most useful thing you can send.

## What helps most

**Tell me what you were building.** If you have ever hand-written `x = r·cos(θ)` to place something in a
user interface, I want to know what it was, what you tried first, and where it got awkward. Open an issue
or write to zoranbuden@gmail.com.

**Report what breaks.** The overlap test is axis-aligned and the solver settles conflicts in the order
elements are given, so there are arrangements it handles badly. A short description and the item list you
used is enough — the demo page is a fine place to reproduce it.

**Say what is missing.** Contact relations between elements are not built. Neither is anything for
headsets. If you need something else before this would be useful to you, that is worth an issue.

## Code contributions

Two patent applications covering the methods here are pending, and the licence is source-available rather
than open source. That combination makes merged code awkward: a contribution would sit inside a codebase
whose rights are not fully settled, and neither of us wants that ambiguity later.

So for now:

- **Issues, bug reports and suggestions** — always welcome, no formalities.
- **Forks and experiments** for the permitted uses in [LICENSE.md](LICENSE.md) — go ahead, no permission
  needed.
- **Pull requests** — please open an issue first. If a change is worth merging, I will ask you to confirm
  in writing that you assign the copyright in that contribution. Small fixes are easier than large ones.

If that is not something you want to do, a fork with your changes is a perfectly good outcome, and I would
still like to hear about it.

## Not a question about the code

Licensing, commercial use, or the patent applications: zoranbuden@gmail.com. If you are unsure whether
your use counts as commercial, just ask.
